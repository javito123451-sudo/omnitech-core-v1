# CORRECCIÓN DE OMNITIME - UNIFICAR EL HISTORIAL DE FICHAJES

He detectado una inconsistencia importante en OmniTime.

## Comportamiento actual

Las pruebas demuestran que:

✅ El fichaje se crea correctamente.

✅ El contador "Fichajes hoy" aumenta.

✅ El panel "Fichajes recientes" muestra el nuevo registro.

Pero:

❌ La pestaña "Fichajes" no muestra esos mismos registros o devuelve un error.

Por tanto el problema NO está en el registro del fichaje.

El problema está en la obtención de los datos para el historial.

----------------------------------------------------

## OBJETIVO

Debe existir UNA ÚNICA fuente de datos para los fichajes.

No quiero varias consultas diferentes.

Crear un único servicio.

Ejemplo:

TimeEntryService

Este servicio será utilizado por:

- Dashboard
- Fichajes recientes
- Pantalla Historial
- Estadísticas
- Exportaciones
- Informes
- IA (AIE)

Todos deben consumir exactamente los mismos datos.

----------------------------------------------------

## AUDITORÍA

Revisar:

- Endpoint utilizado por Dashboard
- Endpoint utilizado por Historial
- Consultas SQL
- Filtros
- Ordenación
- Transformación JSON

Mostrar exactamente dónde divergen.
